## 🏁 はじめに（最終回にあたって）

本シリーズでは、**機械設計を「コードを主語」に再構成する**という視点から、  
形状・寸法・拘束条件・設計ロジックをコードで扱う試みを紹介してきました。

最終回となる本稿では、

- ❓ **Full Code とはどこまでを指すのか**
- ❓ **どこから先は Full Code ではないのか**

という **適用範囲と境界線** を明確にします。

これは新しい発見ではありません。  
多くの設計者が「なんとなく気づいている」ことを、  
**判断基準として言語化**することが本稿の目的です。

---

## 🧠 Full Code の再定義

本シリーズにおける **Full Code** の定義は、次の一点に集約されます。

> 🧩 **設計の一次情報源（SSOT: Single Source of Truth）がコードであること**

GUI、PDF、画像、生成物を否定するものではありません。  
ただしそれらは **成果物・閲覧物** であって、  
**設計の主語にはならない** という立場を取ります。

---

## 🧱 設計をレイヤで分解する

Full Code を正しく扱うため、設計行為を以下のレイヤに分解します。

---

###  🧩 ① Logic（設計意図・ルール）
- 状態遷移（FSM）
- 制御則（PID 等）
- 条件分岐・制約
- RTL 記述（Verilog 等）

👉 **最も Full Code と相性が良い層**

---

###  📐 ② Model（数式・モデル）
- 物理モデル
- V–I 関係
- 状態方程式
- 境界条件

👉 数式は装飾ではなく **設計定義そのもの**  
👉 LaTeX などの記述言語が有効

---

###  📏 ③ Geometry（形状・寸法）
- CAD パラメータ
- 寸法定義
- 拘束条件

👉 GUI 操作ではなく  
👉 **コードで再生成できる形状**が SSOT

---

### 📝 ④ Documentation（設計書）
- 設計意図
- 前提条件
- 数式・図・表

👉 設計書も成果物ではなく  
👉 **ビルドされる設計資産**

---

### ⚙️ ⑤ Build（生成・凍結）
- PDF 生成
- CI（GitHub Actions 等）
- アーティファクト公開

👉 人が「書く」のではなく  
👉 **機械が「生成」するフェーズ**

---

## ✅ Full Code の判定基準（チェックリスト）

実務で使える **判断基準** を示します。

- 🔍 設計変更は **コード差分** として現れるか
- 🔁 成果物（PDF / CAD / Layout）は **再生成可能**か
- 📐 設計意図が **コードや数式で明示**されているか
- 🚫 GUI 操作が **SSOT に混入していない**か
- 🧑‍💻 人が行うのは「判断」であり「転記」ではないか

これらを満たすなら、その工程は **Full Code 適用範囲内**です。

---

## 🚧 どこまでコード化すべきか（境界線）

Full Code は **自動化至上主義**ではありません。

### 🔍 探索フェーズ
- VSCode
- 手動ビルド
- 人間のレビュー

👉 **Human-in-the-loop が必要**

---

### 🔒 凍結フェーズ
- CI
- 自動ビルド
- PDF / データの固定化

👉 **設計成果物として扱う段階**

この **フェーズ分離**ができていないと、  
自動化は設計を壊します。

---

## ⚠️ よくある失敗パターン

### ❌ 生成物が SSOT になる
- PDF が正
- STEP が正
- 画像が正

👉 設計が **更新不能** になる

---

### ❌ 自動化が目的化する
- CI を組んだが設計が進まない
- スクリプトが複雑化する

👉 Full Code は **設計を楽にするための手段**

---

### ❌ 「なんでも Full Code」と呼んでしまう
- 定義が曖昧
- 境界がない

👉 概念が **崩壊** する

---

## 🎯 Full Code Mechanical Design の最終定義

本シリーズの結論は、以下の一文に集約されます。

> 🏗 **設計とは、コードを一次情報源として定義され、  
>  成果物がビルドされる行為である**

機械設計に限らず、

- RTL
- Layout
- Documentation
- Build

すべて **同一の思想** で扱えます。

---

## 🏁 おわりに

本シリーズは、新技術を紹介するものではありません。  
**設計者が無意識にやってきたことを、意識的に揃えただけ**です。

今後、

- 📄 LaTeX で設計書を生成する
- ⚙️ CI で PDF をビルドする
- 👀 GUI を閲覧専用にする

といった話が出てきたとき、  
その是非を判断する **基準点** として、  
本稿が役立てば幸いです。
