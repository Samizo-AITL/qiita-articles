# 007.【Markdown基礎】📝 Markdownは実務ドキュメントの正形式です

## 📌 本記事の位置づけ

本記事は、以降のすべての技術記事・設計メモ・教材に共通する  
**前提基礎知識**を定義するものです。

本プロジェクトでは、  
**Markdown を実務ドキュメントの正形式**として扱います。

---

## ❌ Markdownは「書式」ではありません

Markdownは、見た目を整えるための記法ではありません。  
**情報を構造として記述するための形式**です。

本プロジェクトでは、以下を前提として扱います。

- 🧱 **見出し**：意味構造・章立て
- 📋 **箇条書き**：条件・手順・列挙
- 💻 **コードブロック**：実行可能情報
- 📐 **数式（LaTeX）**：仕様・定義式

---

## 🐍 PythonとMarkdownの関係（実務）

Pythonコード単体では、**実務資産として不十分**です。

実務では、必ず以下の情報が必要になります。

- 処理の目的
- 入力条件
- 出力の意味
- 前提条件

これらは **Markdown に記述します**。

```bash
python main.py
```

という **実行方法の説明も Markdown が正本**です。

---

## 📐 LaTeX数式はMarkdownに埋め込みます

数式は装飾ではなく、**仕様定義**です。  
本プロジェクトでは、LaTeX数式を **Markdown内に直接記述**します。

例：

$$
I = \frac{V}{R}
$$

この形式には、以下の実務的利点があります。

- 📄 数式はテキストとして管理されます
- 🔍 差分管理が可能です
- 🤖 AIにそのまま入力できます

---

## ✅ 前提結論

本プロジェクトでは、以下を前提として固定します。

> 技術文書はすべて Markdown で記述します。  
> Markdown は実務ドキュメントの正形式です。
